- Purpose: define implementation checks for this feature's browser styling, generated content, and public inference endpoints. This is guidance for future development, not a completed repository security assessment.
- Confirmed policy: use Cloudflare Workers AI with a $0 AI-usage budget. Do not add an automatic paid provider, paid upgrade, or credit purchase. Curated/manual styling, saved profiles, and exports stay usable when inference stops.
- Account readiness: unknown. Use official authentication/setup when available; do not infer that an account exists or that credentials are configured. Keep account setup in developer configuration, outside the visitor's design workflow.
- Model status: Llama 3.3 70B Instruct FP8 Fast and Cloudflare-hosted gpt-oss-20b are chat candidates; FLUX.1 Schnell is the initial image candidate. Names, availability, model terms, free eligibility, inference costs, and supporting-service quotas must be rechecked using current official sources before use. There is no tested winner in this handoff.

- Backend route: choose between a Cloudflare Worker with an AI binding and protected REST access from an appropriate existing server after repository/deployment inspection. Verify free allowances for the endpoint, quota store, durable coordination, and any optional abuse checks. Browser code must not call privileged provider APIs with exposed credentials.
- Quota defaults: 3 generated/refined backgrounds and 10 submitted chat prompts per browser per UTC day; a shared ceiling of 8,000 Neurons per UTC day across every visitor and both theme families. Model evaluations consume the same shared capacity. Other account activity can exhaust provider capacity earlier.
- Quota authority: issue/validate an opaque anonymous browser ID and keep counters/reservations on the server. Validate same-browser persistence through reload and cross-origin deployment behavior. An anonymous browser ID is not a verified person; clearing it or using another browser can obtain another browser allowance. Enforce the shared ceiling across all IDs.
- Exact daily accounting: use one coordinated durable authority or an equivalent atomic design for budget admission. In-memory counters, localStorage, and per-location burst limits alone cannot enforce the shared daily budget. Select storage/coordination only after checking its free eligibility and actual consistency guarantees.
- Admission order: validate input/context/identity; determine bounded request cost; reserve both visitor allowance and shared cost atomically or with an equivalently safe coordinated protocol; then dispatch. A failed reservation must not dispatch inference. Bound prompt length, retained context, output tokens, image dimensions/steps, request time, and concurrency to values supported by the selected models.
- Reconciliation: reconcile actual usage when the provider supplies reliable data. If a timeout or interrupted response leaves compute uncertain, retain a conservative charge/reservation; do not refund capacity as if the request never ran. Use idempotency so retries and reconciliation do not duplicate dispatch or undercount usage. Re-evaluate cost estimates when model settings change.
- UTC boundary: identify the accounting day explicitly. Reserve and settle against the correct day even if a response crosses midnight. Test simultaneous requests, retries, delayed responses, provider exhaustion, and quota-store failure. Stop inference when safe bounds, quota state, free access, or provider availability cannot be established.
- Request validation: enforce a server-owned schema and limits for supported operations, allowed preset IDs, appearance values, prompt/context size, and media requests. The browser cannot select arbitrary provider endpoints/models, supply authoritative cost values, or bypass admission with a forged remaining-quota field.
- Browser boundary: use the existing same-origin route when appropriate, or an explicit allowed-origin configuration for a separate endpoint. Validate request origin and applicable CSRF protections; CORS is not authentication or a quota ledger. Check server-held identity and input independently. Add bounded burst protection before expensive work; optional bot checks require server validation and verified free limits.
- Generated theme values: allow only the defined design tokens and safe value formats/ranges. Validate color formats, font choices, button tokens, image IDs, and numeric bounds. Treat returned text as text. Do not execute model instructions, JavaScript, HTML, stylesheets, selectors, or arbitrary CSS expressions. Avoid raw HTML rendering of chat content.
- Generated media: accept only expected response formats/types and bounded dimensions/bytes. Resolve image references through the trusted asset/provider adapter rather than fetching arbitrary user/model URLs from the server. Prevent unsafe URL schemes, path traversal, and untrusted fetch targets. Keep creator/license metadata for curated assets; do not mistake source-page URLs for runtime image paths.
- Credentials and diagnostics: use server-only bindings/secrets and safe configuration examples. No secrets in Git, client-prefixed build variables, source maps, browser storage, exported CSS, screenshots, or logs. Redact sensitive provider errors. Avoid logging full prompts/transcripts by default; document retained operational data and cache bounds.
- Stale proposals: bind responses to a request and target family/preset. A changed active preset or older pending request must not receive an automatic overwrite. Require explicit Apply and revalidate a proposal before modifying the intended profile.
- Local state: validate versioned preference records and cached image metadata, recover unknown IDs and corrupt data, and limit stored bytes. Keep generated bytes out of small localStorage records. Storage errors must retain an operable in-memory session and download/export paths.
- Voice: start listening only after a microphone action, show status and Stop, and populate editable text without sending it automatically. Explain unsupported/denied status concisely and retain typed input. Verify recognition support per target browser; do not claim consistent TV support from desktop mocks.
- Model evaluation: use identical representative seasonal, holiday, High Contrast, invalid-output, and stale-context tasks within bounded input/output settings. Record date, model/settings, sample outputs after removing sensitive data, schema/value validity, latency, and measured usage. Stop on quota/access failure. Enable the chosen route only after free eligibility, quotas, response validation, and fallback tests pass.
- Required failure checks: missing configuration; revoked/invalid credentials; invalid visitor ID; malformed/oversized requests; schema-invalid or unsafe model output; delayed response; quota reservation failure; exhausted visitor/shared/provider allowance; provider timeout; corrupted image; blocked clipboard; denied microphone; and failed persistence. Each must retain the approved manual/curated workflow.
