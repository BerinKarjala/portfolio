- Purpose: provide implementation traceability to the unchanged acceptance records in the v2.2 product plan.
- Initial status: every product check is not implemented/not run. Handoff integrity checks are documented separately and do not count as product tests.
- TDD: derive observable behavior from a check, run an initially failing test, implement the behavior, then record the relevant passing test and command. A grouped test may cover several checks; retain the individual IDs in the ledger.
- Use the repository's existing test runners. Prefer unit tests for resolution/validation/migration/date rules, integration tests for storage/provider/quota contracts, browser tests for route/drawer/export interactions, and focused visual/device review for imagery and accessibility.
- In the repository ledger, record ID, milestone, test file/name, exact command, result, evidence, and any blocking prerequisite. Status must be passed, failed, blocked, or not run. Do not infer passed from a configured provider, green mocks, or asset counts.
- Responsive targets: 360, 390, and 430 CSS-pixel phone widths; a representative tablet; 1440-pixel desktop; 1920×1080 and 3840×2160 TV-class viewports. Verify keyboard/D-pad focus order, readable controls and labels, no off-screen actions, drawer state on resize, and preservation of page navigation/forms. Record physical-TV checks separately.
- Appearance coverage: parameterize every season × Light/Dark × High Contrast on/off, and all four combinations for every shipped holiday. Verify typography, focus, control visibility, and actual text-over-photo crops. The specification's contrast targets are 4.5:1 for normal text, 3:1 for applicable large text, and 3:1 for required non-text control/state cues; inspect varied image regions.
- Accessibility references from the specification: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html ; https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html ; https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html . These are release targets, not a conformance claim.
- Deterministic test seams: inject time, storage availability, provider responses, request ordering, network failures, recognition availability, and quota state. Mock inference must not spend credits or claim live results.
- Critical state sequence: customize Spring, Winter, and two holiday presets independently; give them distinct backgrounds; switch profiles, modes, and families; navigate with drawers open; close/reopen; reload; reset/Undo; restore original appearance and reselect. Assert each profile retains its own intended values.
- Critical asynchronous sequence: submit a proposal for one profile, switch profiles, complete responses out of order, and apply only after explicit review. Older responses cannot silently modify the new active profile.
- Critical budget sequence: race requests for the final visitor allowance and shared budget from multiple IDs/locations; retry and time out requests; cross UTC midnight with in-flight reservations; inject provider exhaustion and ledger failure. Verify conservative admission/settlement and manual fallback.
- Regression coverage: revisit the affected portfolio routes, launchers, forms, navigation, and Page Builder create/preview flows. Run required lint/type/build/test checks after focused feature tests pass. Report existing failures separately.
